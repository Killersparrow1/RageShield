# RageShield v0.1 — Phase 1

A native Kotlin Android starter project for an explicitly enabled, local-first content-filtering assistant.

## What this build does

- Provides a Compose home screen.
- Registers an AccessibilityService scoped to Facebook (`com.facebook.katana`).
- Detects selected accessibility events from Facebook and records the time of the latest event locally.
- Provides a manual, acknowledged test-swipe request through `dispatchGesture`.
- Does **not** automatically swipe, capture screenshots, read captions, record audio, or classify content.

The manual swipe is intentionally not automatic. First validate that the service connects and that the gesture behaves correctly on the target phone. Later phases should only connect a classifier to the swipe controller after the user has explicitly enabled filtering.

## Requirements

- Android Studio (a current stable version)
- JDK 17
- Android SDK Platform 36
- Gradle wrapper generated by Android Studio (see setup below)
- A physical Android phone for accessibility/gesture testing

## Open and build

1. Extract `RageShield-Phase1.zip`.
2. Android Studio → **Open** → select the extracted `RageShield` folder.
3. If Android Studio asks to install SDK Platform 36 or Build Tools, accept.
4. If the project asks for a Gradle JDK, select the bundled JDK 17.
5. Let Gradle sync finish.
6. Connect the phone with USB debugging enabled, or use wireless debugging.
7. Press **Run**.

If Android Studio reports that the Gradle wrapper is missing, use **File → New → New Project** once to let Android Studio install/configure Gradle, or run `gradle wrapper` from a machine with Gradle installed. Then sync again.

## Enable the service on the phone

1. Open RageShield.
2. Tap **Open Accessibility Settings**.
3. Find RageShield under downloaded/installed apps.
4. Open it and enable the service.
5. Read Android's system warning and only proceed if you agree.
6. Return to RageShield and tap **Refresh status**.
7. Open Facebook. Return to RageShield and refresh; the recent-event status should update when Facebook sends a matching accessibility event.

## Test swipe

The test button sends a vertical swipe to the currently visible screen. It is deliberately manual and requires ticking the acknowledgement switch first. For a safe test, use a non-sensitive screen where a swipe will not submit, purchase, delete, or otherwise commit an action. The swipe is not guaranteed to advance a Facebook Reel; Facebook layout and gesture handling can vary.

## Facebook package

The standard Facebook app package is `com.facebook.katana`. Facebook Lite has a different package and is not included in this build.

## Important limitations

- Accessibility events do not reliably identify a Reel versus every other Facebook screen.
- Facebook may change its UI and accessibility tree.
- Android's screenshot API requires API 30+ and an additional service capability; it is not used in this phase.
- This project is a development starter, not a Play Store-ready release.
- Accessibility services are powerful. Keep the purpose visible, obtain the phone user's informed consent, and provide an easy way to turn the service off.
- Do not use the service to secretly monitor private activity.

## Next phase

Implement a conservative screen-state detector and explicit filtering toggle, then add screenshot/OCR analysis. Keep automatic swipe disabled until detection is validated against real examples and false positives are measured.


## Build with GitHub Actions

The repository includes `.github/workflows/android-ci.yml`.

1. Create a **public** GitHub repository named `RageShield` (or your preferred name).
2. Push this project to the repository's `main` branch.
3. Open the repository's **Actions** tab.
4. Open the **Android CI** workflow and wait for it to finish.
5. Open the successful workflow run and download the `RageShield-debug-<commit>` artifact.

The workflow uses JDK 17, `android-actions/setup-android@v4` (which avoids the discontinued `tools` SDK package), Android Platform 36, Build Tools 36.0.0, and Gradle 8.13. It compiles `assembleDebug` and uploads the APK as a 14-day artifact. It does not require signing secrets because this is a debug build.

For a first public repository, review the README, license, accessibility-service disclosure, and privacy behaviour before publishing. Do not commit signing keys, passwords, or other secrets.
